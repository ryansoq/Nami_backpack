### 出生證明閉環驗證系統

今天跟 Ryan 一起完成了遊戲最重要的機制升級！

**閉環驗證流程：**
```
1. payment_tx 確認於 DAA N
         ↓
2. 找 DAA > N 的第一個區塊
   （N+1可能沒區塊，N+2沒，N+3有！）
         ↓
3. 該 DAA 可能有多個區塊
   → 官方排序（blueWork↓, hash↑）
   → 取第一個
         ↓
4. 用該區塊 hash 計算英雄屬性
         ↓
5. inscription 記錄：
   - payment_tx（付費證明）
   - source_hash（命運區塊）
   - card_id = source_daa
   - 屬性
         ↓
6. 驗證：
   inscription → payment_tx → 查鏈 DAA
             → 找下一區塊 → 重算屬性 ✓
```

**關鍵修改：**
- `hero_commands.py`: 新增 `get_first_block_after_daa()`, `get_tx_confirmed_daa()`
- `unified_wallet.py`: 新增 `send_summon_payment()`, `mint_hero_inscription_only()`
- `hero_game.py`: `summon_hero()` 支援 `payment_tx_id` 參數
- 修正順序：先付款 → 後取命運區塊（閉環）

**官方區塊排序規則（來自 rusty-kaspa）：**
```rust
self.blue_work.cmp(&other.blue_work)
    .then_with(|| self.hash.cmp(&other.hash))
```
1. blueWork 大的優先
2. 相同則 hash 字典序小的優先

## 學到的教訓

1. **先付款後取命運**：閉環驗證必須是 payment_tx 確認後才取命運區塊
2. **DAA 不連續**：不是每個 DAA 都有區塊，要找「大於 N 的第一個區塊」
3. **官方排序確定性**：blueWork↓, hash↑ 是確定性規則，任何人都能驗證
4. **一個 TX 綁定所有**：inscription 裡包含 payment_tx + source_hash + 屬性 = 完整閉環
