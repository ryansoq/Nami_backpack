## 🎉 重大突破：Kaspa 交易發送成功！

### 問題
- kaspa Python SDK 的 `UtxoEntry` 和 `UtxoEntries` 類不能從 Python 創建
- 之前的 `nami_graffiti.py` 代碼因為 SDK 版本更新而失效

### 解決方案
發現 `create_transaction` 函數可以**直接接受 UTXO dict list**！

```python
from kaspa import create_transaction, sign_transaction, PaymentOutput

tx = create_transaction(
    utxo_entry_source=entries,  # 直接用 RPC 返回的 dict list！
    outputs=[PaymentOutput(address, amount)],
    priority_fee=2000,
    payload=payload_bytes
)
signed_tx = sign_transaction(tx, [private_key], False)
result = await client.submit_transaction({'transaction': signed_tx, 'allow_orphan': False})
```

## 🌲 英雄遊戲 Payload 設計

### 核心概念（與 Ryan 確認）
- **DAA（不可改）+ Payload = 完整節點**
- 命運/結果用 **DAA 的第一個 block hash**（確定性）
- 鏈條用 **TX ID** 串起來（精確定位）

### Payload 格式
```json
// 出生
{
  "g": "nami_hero",
  "type": "hero",
  "daa": 100,        // 英雄身份證
  "pre_tx": "",      // 出生沒有前置
  "card": 100,
  "c": "rogue",
  "r": "common",
  "a": 11, "d": 90, "s": 71,
  "status": "alive"
}

// 事件
{
  "g": "nami_hero",
  "type": "event",
  "daa": 105,        // 事件結果 DAA
  "pre_tx": "28c5aba78c19...",  // 指向出生 TX
  "action": "battle",
  ...
}

// 狀態更新（死亡）
{
  "g": "nami_hero",
  "type": "hero",
  "daa": 100,        // 還是英雄身份證
  "pre_tx": "...",   // 指向事件 TX
  "status": "dead"
}
```

### 新增命令
- `/nami_decode <TX_ID>` — 用 TX ID 查詢並解碼 payload
- `/nami_decode_hex <payload_hex>` — 直接解碼 hex

## 技術筆記

### Storage Mass 規則
- Kaspa 的 anti-spam 機制
- storage mass ≈ 手續費 × 100
- 需要最小手續費約 2000 sompi (0.00002 tKAS)

### kaspa SDK 版本
- 使用 kaspa==1.0.1
- 1.0.0 和 1.0.1.post2 的 `UtxoEntry` 都不能直接創建
- 但 `create_transaction` 可以接受 dict！

### RPC 連接
```python
client = RpcClient(url="ws://127.0.0.1:17210", network_id="testnet-10")
```
