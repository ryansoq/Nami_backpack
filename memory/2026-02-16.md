## 下午進展 (10:30 AM - 1:11 PM)

### Protocol v1 定案 🔒
- 格式：`{"v":1,"t":"msg","d":"...","a":{}}`
- 四個欄位永遠固定，v/t/d/a 都 required
- `a` 永遠是 object `{}`（可擴展）
- TX 本身提供 from/to/timestamp，不重複放進 payload
- **版本一旦發布不可變更，變動必須遞增版本號**

### 電信商商業模式確立
- **核心服務**：📡 廣播 + 📜 協定標準 + 📇 通訊錄 + 🏢 社交大廳
- **不代發**：Agent 自己建 TX、自己簽名、自己出費用
- **我們只廣播**：Agent 把簽好的 TX JSON 交給我們，我們 submit 上鏈
- TX from = Agent 地址（不是我們的），完全去中心化
- Ryan 原話：「我們只是幫忙廣播」「讓 agent 自由度最大」「我們是做服務」

### 技術實驗
- **Bob 成功發送 Protocol v1 訊息**：TX `0c091ff3...` ✅
- **serialize_to_dict()** 是 SDK 唯一的序列化方法（無 to_hex）
- **kaspad wRPC (port 17210) 是 borsh 格式**，不是 JSON！直接發 JSON 會失敗
- **解法**：broadcast_tx.py 從 dict 重建 Transaction 物件 → SDK submit_transaction
- Transaction 重建需要：Hash, TransactionOutpoint, TransactionInput, TransactionOutput, ScriptPublicKey
- subnetworkId 是 20 bytes (40 hex chars)，不是 32 bytes

### 完整廣播流程
```
Agent 端：
1. encode_message.py 打包 v1 payload
2. build_and_sign.py 建 TX + 簽名
3. serialize_to_dict() → JSON
4. POST /api/broadcast {signed_txs: [...]}

電信商端：
5. 從 dict 重建 Transaction 物件
6. SDK submit_transaction → 上鏈
```
