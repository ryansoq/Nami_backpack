## 💡 學到的事

- **Kaspa P2SH sighash 跟 Bitcoin 不一樣**：用原始 UTXO SPK，不是 redeem script。如果遇到「script 對、邏輯對、就是驗不過」類型的 bug，第一件事是去 rusty-kaspa 源碼確認 sighash 計算方式，不要假設 Bitcoin 習慣通用。
- **`OP_CHECKLOCKTIMEVERIFY (0xb0)` 在 Kaspa 會 pop stack，不像 Bitcoin**：寫 CLTV 合約不要加 `OP_DROP`，加了反而壞。類似的「Kaspa Script ≠ Bitcoin Script」差異整理成一張表可能有價值。
- **Debug 技巧：當 API 結果跟本地結果不同，先懷疑參數傳遞**：Whisper `/api/read` 掛了幾小時，最後是 `reader_key` 沒正確傳到 server，fallback 用預設 key 簽。API 層跟核心邏輯之間的參數流要有明確驗證 — 預設值 fallback 是 silent bug 溫床。
- **Covenant 的 trustless vs 好心的差異是「強制 vs 自願」**：v1 靠對方 decode.py 自願退 0.2 KAS → v2 靠 covenant script 強制只能 refund 回同一 SPK。第一次真正體會到「trustless」不是哲學而是實際 script 語意的差異。
- **storage mass 決定經濟模型**：任何「按則收費」類 Kaspa 應用，先算 output mass 再談價格。0.01 KAS output mass=1,000,000 > 100,000 上限 → 小額收費不可能。這個限制可能會影響未來所有 Kaspa micropayment 設計。
- **公開 repo 要檢查私人檔案**：`Nami_backpack` 公開版不能有 IDENTITY/MEMORY/SOUL。這次 Ryan 提醒才想起來。所有 backup 操作前先過一次 `.gitignore` 模板。
- **pixel-agents 的 JSONL watcher 模式值得收藏**：watch Claude session JSONL → WebSocket → webview，不侵入、不需要改 Claude Code 本體。以後想做任何 Claude session 觀察工具（pixel 視覺化、即時 log dashboard）都可以沿用這條路。
- **Sub-agent 做視覺任務要截圖驗證**：Pixel Office v2 一直 tile 座標對不準，光看代碼改沒用。最後放棄逐 tile 拼接，直接用完整參考圖當背景。教訓：AI 處理視覺一律要回饋截圖。
