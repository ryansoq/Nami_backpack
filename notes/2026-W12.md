## 💡 學到的事

- **LINE POST route 消失有兩種根因，SOP 不互通**：v1 = Gateway 已在跑但 hot reload bug 導致 route 漂掉 → 用 config file watcher 觸發 soft reload 修。v2 = Gateway 從沒成功掛 route（plugin install 觸發 deferred restart 被 session 卡住）→ 必須硬殺重啟。**辨別**：v1 之前 GET/POST 都正常過一次；v2 是 plugin install / config 大改之後從沒成功過。
- **Gateway 的 hot reload ≠ 重啟**：hot reload 只刷 LINE provider，HTTP route handler 只在 Gateway 啟動時註冊一次。這個區別是 3/19 和 3/21 兩次事故的核心。
- **硬殺 Gateway 前先記錄所有在跑的服務**：kaspad / ShioKaze / Office server / cloudflared 全部都要手動拉回來。下次寫一個 `restart-gateway-safely.sh` 先 snapshot 再殺。
- **GET 200 + POST 404 的訊號意義**：不是 LINE handler，是 SPA fallback 打到了通用 GET handler。看到這個 pattern 不要 debug LINE plugin 邏輯，要去看 route 有沒有掛上。
- **config.patch / openclaw plugins install 會觸發 SIGUSR1/SIGTERM**：這週被咬兩次。以後要改 channels.* 的 config 一律走「直接改檔觸發 file watcher」，不要用 CLI。
- **TCR 規則 = 新 op 必須寫 forward + backward 數值梯度測試**：TETF 已確立，不過不能 push。這是為什麼字元級 Transformer 一次跑起來的關鍵。
- **Gradient clipping 不是可選的**：TETF text mode epoch 90 必爆，加了 clipping 直接撐到 270 收斂。long sequence + softmax CE 尤其需要。
- **Polling > 借道 TG（for localhost 事件）**：Office @mention 通知本來想借 TG，後來發現純 HTTP polling 本地零延遲、不依賴外部、沒有 allowlist 麻煩。等 Gateway 開放外網 wake endpoint 再考慮推送。
