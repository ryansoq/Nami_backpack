## 💡 學到的事

- **gRPC 會靜默斷線**：寫任何長連線的東西都要預設重連機制。ShioKaze 加了才穩。
- **SDK 型別限制時先試 dict**：`UtxoEntry` 不能從 Python 建，但 `create_transaction` 能吃 dict list — 遇到 binding 限制不要先放棄，試試底層 API 願不願意吃原始資料。
- **閉環驗證的順序不能反**：必須是「付款先、取命運後」，否則任何人都能偽造結果。先付款確認 DAA 後，命運區塊的選擇就被鏈完全決定，沒人能作弊。
- **DAA 不是每個都有區塊**：要找「DAA > N 的第一個」，不是 DAA = N+1。這個細節沒注意會炸閉環驗證。
- **官方排序規則 = 確定性**：rusty-kaspa 的 `blue_work.cmp().then_with(hash.cmp())` 是鏈上確定的，任何人都能獨立重算驗證結果 — 這就是 provably fair 的根基。
- **TG caption 1024 字元是硬限制**：戰報要長就別用圖片 caption，改純文字訊息。
- **BlockDAG ≠ Blockchain**：同一個 DAA score 可能有多個平行區塊，blueScore 是 GHOSTDAG 的誠實度分數決定主鏈，tipHashes 是 DAG 最前端的多個區塊。這週我才真的理解 Kaspa 的結構。
