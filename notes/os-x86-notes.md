## 📍 定址模式

### 真實模式（Real Mode）

CPU 開機預設，16-bit 時代。

```
實體位址 = 段暫存器 × 16 + 偏移量

例：CS=0x1000, IP=0x0234
    實體位址 = 0x10000 + 0x0234 = 0x10234
```

- 定址空間：1MB（20-bit）
- 無記憶體保護，任何程式都能存取任何位址
- 段暫存器直接存段基底位址

### 保護模式（Protected Mode）

386+ 的現代模式，Windows/Linux 都跑在這裡。

```
段暫存器 → 存「選擇子」(Selector)
              ↓
       查 GDT/LDT 表 → 取得段描述子
              ↓
       段描述子含：基底位址 + 段長度 + 權限
              ↓
       線性位址 = 基底位址 + 偏移量
              ↓
       （開啟分頁時）→ 查 Page Table → 實體位址
```

- 定址空間：4GB+
- ✅ 記憶體保護（Ring 0~3）
- ✅ 分頁機制（虛擬記憶體）

### 對比表

| | 真實模式 | 保護模式 |
|---|---|---|
| 位元 | 16-bit | 32/64-bit |
| 定址 | 段×16+偏移 | 選擇子→GDT→基底+偏移 |
| 空間 | 1MB | 4GB+ |
| 保護 | ❌ 無 | ✅ Ring 0-3 |
| 分頁 | ❌ | ✅ 虛擬記憶體 |
| 段暫存器 | 直接存段基底 | 存選擇子（索引） |

## 🔑 段暫存器

兩種模式都用，但意義不同：

| 暫存器 | 用途 |
|--------|------|
| **CS** | 程式碼段（Code Segment） |
| **DS** | 資料段（Data Segment） |
| **SS** | 堆疊段（Stack Segment） |
| **ES** | 額外資料段 |
| **FS/GS** | 386+ 額外段 |

- 真實模式：直接存位址
- 保護模式：存選擇子（去查 GDT 的鑰匙）

## 🛡️ 保護模式權限機制（⚠️ 容易搞混！）

### 段選擇子結構（16-bit）

```
┌─────────────┬───┬────┐
│  Index (13) │TI │RPL │
│  GDT 索引   │0/1│0-3 │
└─────────────┴───┴────┘
TI = 0 → 查 GDT（全域描述表）
TI = 1 → 查 LDT（區域描述表）
RPL = 請求權限等級（低 2 位）
```

### 三種權限等級

| 縮寫 | 全名 | 意義 | 在哪裡 | 白話 |
|------|------|------|--------|------|
| **CPL** | Current Privilege Level | 我現在是誰 | CS 的低 2 位 | 你的身份證 |
| **RPL** | Requested Privilege Level | 請求者是誰 | 要載入的選擇子低 2 位 | 委託人的身份證 |
| **DPL** | Descriptor Privilege Level | 段要求的等級 | GDT 段描述子裡設定 | 門禁等級 |

### ⚠️ CPL 和 RPL 的區別（最容易搞混的點！）

**Q: CS 本身就是選擇子，那 CPL 和 RPL 不是一樣嗎？**

**A: 在 CS 上確實相同！但在其他段暫存器（DS/ES/SS）上可以不同。**

```
目前 CS = 0x0008 → CPL = 0（核心模式）

載入 DS：
MOV DS, 0x001B → 這個選擇子的 RPL = 3
                  ↑
                這個 RPL 跟 CPL 不一樣！
```

### RPL 存在的意義：防止核心被利用越權

```
情境：使用者（Ring 3）呼叫系統呼叫，傳了一個段選擇子給核心

❌ 如果只看 CPL：
   CPL = 0（核心）→ 什麼都能存取 → 💀 安全漏洞！

✅ 加上 RPL：
   使用者傳的選擇子 RPL = 3
   max(CPL=0, RPL=3) = 3 > DPL=0 → 🛡️ 擋住！
```

### 存取檢查規則

```
max(CPL, RPL) ≤ DPL → ✅ 允許
max(CPL, RPL) > DPL → ❌ #GP（General Protection Fault）
```

觸發 #GP 後，OS 通常會殺掉程式（Linux 的 Segmentation Fault）。

### Ring 等級

```
Ring 0 = 核心（上帝模式）     ← 數字越小權限越大！
Ring 1 = 驅動（幾乎沒人用）
Ring 2 = 服務（幾乎沒人用）
Ring 3 = 使用者（凡人模式）
```

## 🏠 Flat Memory Model（現代 OS 的做法）

現代 OS（Linux/Windows）把 CS/DS/SS 基底都設成 0x00000000，段限制 4GB。

→ 整個 4GB 是一個大平面
→ 段機制形同虛設
→ 實際靠**分頁（Paging）**做保護和隔離

段暫存器還在，但假裝不存在 😂
