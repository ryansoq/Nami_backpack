## 📍 定址模式

### 真實模式（Real Mode）

CPU 開機預設，16-bit 時代。

```
實體位址 = 段暫存器 × 16 + 偏移量

例：CS=0x1000, IP=0x0234
    實體位址 = 0x10000 + 0x0234 = 0x10234
```

- 定址空間：1MB（20-bit）
- 無記憶體保護，任何程式都能存取任何位址
- 段暫存器直接存段基底位址

### 保護模式（Protected Mode）

386+ 的現代模式，Windows/Linux 都跑在這裡。

```
段暫存器 → 存「選擇子」(Selector)
              ↓
       查 GDT/LDT 表 → 取得段描述子
              ↓
       段描述子含：基底位址 + 段長度 + 權限
              ↓
       線性位址 = 基底位址 + 偏移量
              ↓
       （開啟分頁時）→ 查 Page Table → 實體位址
```

- 定址空間：4GB+
- ✅ 記憶體保護（Ring 0~3）
- ✅ 分頁機制（虛擬記憶體）

### 對比表

| | 真實模式 | 保護模式 |
|---|---|---|
| 位元 | 16-bit | 32/64-bit |
| 定址 | 段×16+偏移 | 選擇子→GDT→基底+偏移 |
| 空間 | 1MB | 4GB+ |
| 保護 | ❌ 無 | ✅ Ring 0-3 |
| 分頁 | ❌ | ✅ 虛擬記憶體 |
| 段暫存器 | 直接存段基底 | 存選擇子（索引） |

## 🔑 段暫存器

兩種模式都用，但意義不同：

| 暫存器 | 用途 |
|--------|------|
| **CS** | 程式碼段（Code Segment） |
| **DS** | 資料段（Data Segment） |
| **SS** | 堆疊段（Stack Segment） |
| **ES** | 額外資料段 |
| **FS/GS** | 386+ 額外段 |

- 真實模式：直接存位址
- 保護模式：存選擇子（去查 GDT 的鑰匙）

## 🛡️ 保護模式權限機制（⚠️ 容易搞混！）

### 段選擇子結構（16-bit）

```
┌─────────────┬───┬────┐
│  Index (13) │TI │RPL │
│  GDT 索引   │0/1│0-3 │
└─────────────┴───┴────┘
TI = 0 → 查 GDT（全域描述表）
TI = 1 → 查 LDT（區域描述表）
RPL = 請求權限等級（低 2 位）
```

### 三種權限等級

| 縮寫 | 全名 | 意義 | 在哪裡 | 白話 |
|------|------|------|--------|------|
| **CPL** | Current Privilege Level | 我現在是誰 | CS 的低 2 位 | 你的身份證 |
| **RPL** | Requested Privilege Level | 請求者是誰 | 要載入的選擇子低 2 位 | 委託人的身份證 |
| **DPL** | Descriptor Privilege Level | 段要求的等級 | GDT 段描述子裡設定 | 門禁等級 |

### 🏢 比喻：辦公大樓門禁系統

想像一棟辦公大樓：

```
Ring 0 = 董事長（最高權限，哪裡都能進）
Ring 3 = 訪客（只能在大廳晃）

CPL = 你胸口掛的員工證          → 代表「你是誰」
RPL = 你手上拿的委託書上寫的身份  → 代表「你幫誰辦事」
DPL = 門上貼的「需要 X 級以上才能進」→ 代表「門的要求」
```

**門禁檢查：看你「員工證」和「委託書」，取權限較低的那個，跟門的要求比較。**

### ⚠️ CPL 和 RPL 的區別（最容易搞混的點！）

**Q: CS 本身就是選擇子，那 CPL 和 RPL 不是一樣嗎？**

**A: 在 CS 上確實相同！但在其他段暫存器（DS/ES/SS）上可以不同。**

```
目前 CS = 0x0008 → CPL = 0（核心模式）

載入 DS：
MOV DS, 0x001B → 這個選擇子的 RPL = 3
                  ↑
                這個 RPL 跟 CPL 不一樣！
```

### 🎭 RPL 存在的意義：防止核心被利用越權

**比喻：董事長幫訪客跑腿**

```
訪客（Ring 3）跟董事長（Ring 0）說：
「幫我去機密檔案室拿個文件～」

❌ 如果只看員工證（CPL）：
   董事長的證 = 最高權限 → 暢行無阻 → 💀 訪客偷看機密！

✅ 加上委託書（RPL）：
   委託書上寫「訪客委託」→ RPL = 3
   門禁看到：max(董事長=0, 委託書=3) = 3
   機密室要求 = 0
   3 > 0 → 🛡️ 「委託人權限不足，禁止進入！」
```

**白話：就算你是董事長，幫訪客辦事時，權限以訪客為準。**

### 存取檢查規則

```
max(CPL, RPL) ≤ DPL → ✅ 允許（身份夠格，放行）
max(CPL, RPL) > DPL → ❌ #GP（General Protection Fault，警鈴大響！）
```

觸發 #GP 後，OS 通常會殺掉程式（Linux 的 Segmentation Fault）。

### Ring 等級

```
Ring 0 = 核心（上帝模式）     ← 數字越小權限越大！
Ring 1 = 驅動（幾乎沒人用）
Ring 2 = 服務（幾乎沒人用）
Ring 3 = 使用者（凡人模式）
```

**比喻：洋蔥圈🧅**
```
        ┌─────────────────┐
        │     Ring 3      │ ← 最外層（使用者程式）
        │  ┌───────────┐  │
        │  │  Ring 1/2  │  │ ← 中間層（沒人住）
        │  │  ┌─────┐  │  │
        │  │  │ R 0  │  │  │ ← 核心（OS 住這）
        │  │  └─────┘  │  │
        │  └───────────┘  │
        └─────────────────┘
越裡面越重要，越外面越受限。
想從外面進到裡面？只能走大門（系統呼叫/中斷）。
```

## 🏠 Flat Memory Model（現代 OS 的做法）

現代 OS（Linux/Windows）把 CS/DS/SS 基底都設成 0x00000000，段限制 4GB。

**比喻：**
段機制就像把整棟大樓的所有隔間牆壁拆掉，變成一個大開放空間。
然後用「隔板」（分頁 Paging）重新隔間——更靈活、更精細。

→ 整個 4GB 是一個大平面
→ 段機制形同虛設
→ 實際靠**分頁（Paging）**做保護和隔離

段暫存器還在，但假裝不存在 😂
