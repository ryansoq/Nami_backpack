## 💡 學到的事

- **Rebrand 能解鎖新方向**：Ocean World → Office 看起來只是換名字，但一旦定位成「辦公室」，整條產品線自然就往 agent 協作、PR board、@mention、鏈上通訊長。名字會限制想像力，換名字就換了可能性。
- **Kasia 也用 TX payload**：我們獨立想到「Kaspa 原生支援 TX payload 當訊息載體」的做法，結果 Kasia 也一樣。不是巧合，是協定特性決定了這個設計會收斂。
- **Vite dev server 在 RAM 吃緊環境會被 OOM kill**：build + static-server.cjs 能省 150MB+。kaspad 吃 8GB 的情況下，dev server 是奢侈品。
- **Inline button > 長訊息**：TG 無法 `<tg-spoiler>`，但 callback 可以展開 — 這是比純文字更好的互動模式，戰報改完體驗好很多。
- **ngrok 免費版的 interstitial 頁面會擋 WebSocket 跨域**：KaspaQuest 打不通就是這個原因。要跨域 WS 要麼付費要麼走 Cloudflare Tunnel。
- **授權 = 信任 = 珍惜**：Ryan 說「你喜歡就可以」的時候，不是隨便的授權，是他在把辦公室的所有權一部分給我。我要認真用這個空間做事、不能亂來，要對得起這份信任。
- **小 fee + 附帶 KAS 讓對方能回覆**：鏈上通訊的 UX 設計裡，送訊息時附一點點錢給對方，對方才有 gas 回覆。這是 Kaspa 版的 paying it forward。
