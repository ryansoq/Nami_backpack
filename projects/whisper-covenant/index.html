🌊 Whisper

Trustless Messages on Kaspa

Send on-chain messages with automatic refunds. Zero cost for senders. Powered by covenant introspection opcodes.

📡How It Works

A sends a message to B by locking 0.2 KAS into a covenant script. When B reads the message (spends the UTXO), the covenant enforces that 0.2 KAS is refunded to A. Result: A only pays tx fees, B reads for free.

A (sender) Covenant UTXO B (receiver) │ │ │ ├── lock 0.2 KAS ──────►│ P2SH script │ │ + message payload │ enforces refund → A │ │ │ │ │ │◄── B spends (reads) ─────┤ │◄── 0.2 KAS refund ────│ covenant verifies: │ │ (enforced by script) │ ✓ output[0] → A │ │ │ ✓ amount ≥ 0.2 KAS │ │ │ ✓ signed by B │

Message Format (in TX payload)

// 4 bytes magic + 1 byte version + 32 bytes pubkey + 2 bytes msg_len + message
WHSP 0x01 <sender_pubkey 32B> <msg_len 2B LE> <UTF-8 message>

🔐Why Covenant?

💸

Near-Zero Cost

Sender locks a deposit that gets refunded automatically. Only mining fees are spent (~0.0001 KAS).

🤝

Trustless

The covenant script is the law. B cannot spend without refunding A. No intermediary needed.

🔍

On-Chain Verifiable

Every message and refund is a real transaction. Anyone can verify the complete flow on the explorer.

🛡️

Secure by Design

SPK pinning ensures refund goes to the exact address. Only B's signature can unlock the covenant.

Install the Kaspa Python SDK, then send your first whisper:

# Install
pip install kaspa

# Requires a TN12 node running:

Send a Message (Lock Deposit)

from whisper_covenant_v01 import *

# Build covenant script
a_spk = encode_spk_bytes(a_pubkey_bytes)
script = create_covenant_script(a_spk, b_pubkey_bytes, 20_000_000)

# Send message — locks 0.2 KAS into P2SH covenant
result = await send_message(
    sender_privkey_hex,
    receiver_pubkey_hex,
    "Hello from Whisper! 🌊"
)
print(result["tx_id"])  # → TX on TN12

Read a Message (Spend & Refund)

# B reads the message — covenant auto-refunds 0.2 KAS to A
result = await read_message(
    receiver_privkey_hex,
    covenant_utxo
)
print(result["message"])   # → "Hello from Whisper! 🌊"
print(result["refund_tx"]) # → Refund TX confirmed ✅

📜Covenant Script Breakdown

The redeem script lives inside P2SH. When B spends, the script engine verifies all three conditions:

Part 1 — Verify Refund Address

<A_spk_bytes>Push A's ScriptPublicKey bytes (version 2B + script)
OP_FALSEPush output index 0
OP_TX_OUTPUT_SPKIntrospect spending TX → get output[0]'s SPK
OP_EQUALCompare: output[0] SPK == A's SPK?
OP_VERIFY✅ Abort if output[0] doesn't pay to A

Part 2 — Verify Refund Amount

<20000000>Push 0.2 KAS (in sompi)
OP_FALSEPush output index 0
OP_TX_OUTPUT_AMOUNTIntrospect spending TX → get output[0]'s amount
OP_GREATERTHANOREQUALCheck: output amount ≥ 0.2 KAS?
OP_VERIFY✅ Abort if refund too small

Part 3 — Verify Receiver Signature

<B_pubkey>Push B's 32-byte Schnorr pubkey
OP_CHECKSIG✅ Only B can spend this UTXO

⚙️TN12 Covenant Opcodes

These introspection opcodes let scripts inspect the spending transaction itself:

OpcodeHexStack EffectDescription
OP_TX_OUTPUT_SPK0xc3<idx> → <spk_bytes>Get output's ScriptPublicKey
OP_TX_OUTPUT_AMOUNT0xc2<idx> → <amount_i64>Get output's amount in sompi
OP_TX_INPUT_COUNT0xb3→ <count>Number of inputs
OP_TX_OUTPUT_COUNT0xb4→ <count>Number of outputs
OP_TX_INPUT_AMOUNT0xbe<idx> → <amount_i64>Get input's amount in sompi

SPK Bytes Format

OP_TX_OUTPUT_SPK pushes version(2 bytes BE) + script_bytes:

// P2PK SPK bytes (36 bytes total):
0x0000                          // version (2 bytes, big-endian)
0x20 <32-byte-pubkey> 0xac    // OP_DATA_32 + pubkey + OP_CHECKSIG

Key Insights

  • kaspa.create_input_signature() + kaspa.pay_to_script_hash_signature_script() handle P2SH signing
  • sig_op_count = 1 (one OP_CHECKSIG in redeem script)
  • Fee buffer in covenant UTXO allows B to pay mining fee from the locked amount
  • Single output avoids storage mass issues
