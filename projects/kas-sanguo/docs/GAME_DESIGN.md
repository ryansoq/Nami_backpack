## 1. 概述

### 1.1 一句話描述

> 在三國地圖上佔城、練兵、出征，用 Kaspa 區塊鏈代幣 (tKAS) 驅動一切經濟活動的即時策略 Web 遊戲。

### 1.2 設計目標

| 目標 | 說明 |
|------|------|
| **即時策略** | 行軍需要真實時間，不是回合制，玩家需持續關注局勢 |
| **區塊鏈經濟** | tKAS 是唯一貨幣，鏈上結算保證透明公平 |
| **手機優先** | 主要在手機瀏覽器遊玩，隨時查看行軍狀態 |
| **社交博弈** | 結盟、背刺、外交，人與人的互動是核心樂趣 |
| **低門檻** | 免安裝，開瀏覽器就能玩，新手 5 分鐘上手 |

### 1.3 參考遊戲

- **Web 三國** — 即時行軍、城池攻防的核心體驗
- **部落衝突 (Clash of Clans)** — 簡潔的兵種系統、升級節奏
- **文明帝國 (Civilization)** — 地圖戰略縱深、外交系統

### 1.4 目標平台

- 手機瀏覽器（iOS Safari / Android Chrome）— 主要
- 桌面瀏覽器 — 次要
- 不需要安裝 App

## 2. 世界觀與背景

### 2.1 時代設定

東漢末年，天下大亂。各路諸侯割據一方，爭奪城池與資源。

但這個世界有一點不同——城池地底蘊藏著一種神秘的礦脈「**KAS 礦**」。誰佔領城池，誰就能開採 KAS，用來招兵買馬、擴張勢力。

### 2.2 世界觀核心

- 城池 = 礦場，佔城 = 佔礦
- tKAS 是這個世界的唯一通貨
- 武將的能力由「天命」（區塊 hash）決定，不可篡改
- 沒有絕對的善惡，只有利益與策略

### 2.3 地圖

以三國時期中國地圖為基礎，簡化為 **數十座城池** 與連接道路的網絡圖。

城池分佈於九州：司隸、冀州、兗州、豫州、徐州、青州、揚州、荊州、益州、涼州、幽州、并州。

## 4. 城池系統

### 4.1 城池分級

| 等級 | 名稱 | tKAS 產出/時 | 數量 | 代表城池 |
|------|------|-------------|------|----------|
| S | 帝都 | 100 | 2 | 洛陽、長安 |
| A | 州府 | 60 | 5 | 許昌、成都、建業、鄴城、襄陽 |
| B | 大城 | 30 | 10 | 漢中、江陵、壽春、下邳… |
| C | 中城 | 15 | 15 | 新野、汝南、廬江… |
| D | 小城 | 5 | 若干 | 各郡小城 |

### 4.2 城池屬性

```typescript
interface City {
  id: string;               // 唯一識別
  name: string;             // 城池名（許昌、洛陽…）
  tier: 'S' | 'A' | 'B' | 'C' | 'D';
  position: { x: number; y: number };  // 地圖座標
  owner: string | null;     // 玩家 ID，null = NPC / 空城
  garrison: Army[];         // 駐軍
  defense: DefenseLevel;    // 城防等級
  production: number;       // tKAS/小時
  connections: string[];    // 相鄰城池 ID（行軍路線）
}
```

### 4.3 城池機制

- **產出**：每小時結算一次，tKAS 自動進入城主錢包
- **佔領**：攻方清除守軍後，城池歸攻方所有
- **空城**：無人佔領的城由 NPC 守軍駐守（依等級強弱不同）
- **首都**：每位玩家有一座「首都」，首都被攻破不會消滅玩家，但會失去大量資源

### 4.4 城池連接（道路網絡）

城池之間以道路連接，行軍只能沿道路移動。地圖為一個**加權圖**，邊的權重 = 行軍距離（時間）。

```
洛陽 ──(3h)── 許昌 ──(2h)── 汝南
  │                          │
(4h)                       (2.5h)
  │                          │
長安 ──(5h)── 漢中 ──(4h)── 襄陽
```

## 5. 兵種系統

### 5.1 兵種一覽

| 兵種 | 移動速度 | 攻擊力 | 防禦力 | 特性 | 訓練費 (tKAS/兵) |
|------|----------|--------|--------|------|-------------------|
| 🐴 騎兵 | 快 (×1.5) | 高 (8) | 低 (3) | 突擊加成，剋步兵 | 3 |
| 🛡️ 步兵 | 慢 (×1.0) | 中 (5) | 中 (6) | 平衡，剋弓兵 | 1.5 |
| 🏹 弓兵 | 中 (×1.2) | 中 (6) | 低 (4) | 守城 +50%，剋騎兵 | 2 |
| 🔥 計策兵 | 慢 (×0.8) | 特殊 | 低 (2) | 火攻/水攻等 AOE | 5 |

### 5.2 剋制關係

```
    騎兵
   ↗    ↘
步兵  ←  弓兵

計策兵：不參與剋制三角，獨立技能效果
```

- **騎兵 剋 步兵**：騎兵衝鋒，對步兵傷害 ×1.5
- **步兵 剋 弓兵**：步兵近身肉搏，弓兵無法遠射，傷害 ×1.5
- **弓兵 剋 騎兵**：弓兵齊射，騎兵防低易中箭，傷害 ×1.5
- **計策兵**：AOE 傷害，不受剋制影響，但自身脆弱

### 5.3 訓練機制

- 訓練消耗 tKAS + 時間
- 每座城池有「兵營」，一次可訓練的數量取決於兵營等級
- 訓練完成的兵駐紮在該城

```
訓練時間 = 基礎時間 × 數量 / 兵營等級
騎兵基礎：30 分/兵
步兵基礎：15 分/兵
弓兵基礎：20 分/兵
計策兵基礎：60 分/兵
```

## 6. 即時行軍系統

### 6.1 核心規則

- 出兵後，部隊以**真實時間**在地圖上移動
- 行軍速度取決於**最慢兵種**（木桶效應）
- 地圖上顯示行軍箭頭，所有玩家可見（偵察範圍內）
- 行軍途中**不可取消**（一旦出發就回不了頭）
- 可以在行軍途中**變更目的地**（但需額外時間）

### 6.2 行軍時間計算

```
行軍時間 = 路線距離 / 部隊速度

部隊速度 = min(各兵種速度) × 武將加成

路線距離 = 起點城到目的城的最短路徑權重總和
```

### 6.3 行軍狀態

```typescript
interface March {
  id: string;
  owner: string;            // 玩家 ID
  general: General;         // 領兵武將
  troops: TroopStack[];     // 兵種與數量
  origin: string;           // 起點城 ID
  destination: string;      // 目的城 ID
  path: string[];           // 途經城池
  departTime: number;       // 出發時間戳
  arriveTime: number;       // 預計到達時間戳
  status: 'marching' | 'battling' | 'returning';
}
```

### 6.4 偵察系統

- 每座城池有**視野範圍**，範圍內的行軍箭頭可見
- 預設視野 = 相鄰 1 座城的範圍
- 升級「烽火台」可擴展視野到相鄰 2-3 座城
- 聯盟成員共享視野

### 6.5 行軍消耗

行軍消耗 tKAS 作為糧草：

```
糧草消耗 = 兵力總數 × 行軍時間(小時) × 0.1 tKAS
```

如果玩家 tKAS 不足以支付糧草，部隊會**逃散**（每小時損失 10% 兵力）。

## 7. 戰鬥系統

### 7.1 戰鬥觸發

部隊到達目的城後，如果城內有敵方守軍，自動進入戰鬥。

### 7.2 戰鬥計算

戰鬥為**自動結算**，不需要玩家操作。結果由以下因素決定：

```
戰鬥力 = Σ(兵種攻擊力 × 數量 × 剋制係數) × 武將加成 × 地形加成

攻方戰鬥力 vs 守方戰鬥力
```

#### 剋制係數

| 攻方 \ 守方 | 騎兵 | 步兵 | 弓兵 |
|-------------|------|------|------|
| 騎兵 | 1.0 | 1.5 | 0.7 |
| 步兵 | 0.7 | 1.0 | 1.5 |
| 弓兵 | 1.5 | 0.7 | 1.0 |

#### 武將加成

```
武將加成 = 1 + (武將統率 / 100) + 技能加成
```

#### 守城加成

```
守方加成 = 1 + (城防等級 × 0.1) + 弓兵守城加成(0.5)
```

### 7.3 戰鬥結果

```
若 攻方戰鬥力 > 守方戰鬥力：
  攻方勝，佔領城池
  攻方損失 = 攻方兵力 × (守方戰鬥力 / 攻方戰鬥力) × 0.6
  守方損失 = 全軍覆沒（殘兵潰散）

若 攻方戰鬥力 ≤ 守方戰鬥力：
  守方勝，攻方撤退（殘兵返回出發城）
  守方損失 = 守方兵力 × (攻方戰鬥力 / 守方戰鬥力) × 0.4
  攻方損失 = 攻方兵力 × 70%
```

### 7.4 戰利品

勝方獲得：
- 敗方城池中未被消耗的 tKAS（50%）
- 城池控制權
- 小概率俘虜敵方武將

### 7.5 戰報

每次戰鬥生成戰報，記錄：
- 雙方兵力、武將
- 戰鬥過程（回合制模擬，純展示用）
- 最終結果與損失
- 戰利品

## 8. 武將系統

### 8.1 武將屬性

```typescript
interface General {
  id: string;             // 鏈上唯一 ID
  name: string;           // 武將名
  portrait: string;       // 頭像
  stats: {
    command: number;      // 統率 (1-100)：影響帶兵上限與戰鬥加成
    force: number;        // 武力 (1-100)：影響單挑與突擊
    intellect: number;    // 智力 (1-100)：影響計策成功率
    politics: number;     // 政治 (1-100)：影響城池產出加成
    charisma: number;     // 魅力 (1-100)：影響招兵速度
  };
  skills: Skill[];        // 技能列表
  level: number;          // 等級 (1-50)
  experience: number;     // 經驗值
  owner: string;          // 擁有者玩家 ID
  origin: string;         // 來源區塊 hash（不可竄改）
}
```

### 8.2 武將招募

- 花費 tKAS 進行「求賢」
- 武將屬性由 **Kaspa 區塊 hash** 決定，確保公平隨機
- 求賢費用越高，出現高品質武將的機率越大

```
求賢費用層級：
  - 草廬求賢：10 tKAS → 普通武將 (屬性 30-60)
  - 黃金求賢：50 tKAS → 優秀武將 (屬性 50-80)
  - 天命求賢：200 tKAS → 傳奇武將 (屬性 70-99)
```

#### Hash 決定屬性演算法

```
取最新 Kaspa 區塊 hash
hash_bytes = hex_to_bytes(block_hash)

command  = hash_bytes[0] % range + base
force    = hash_bytes[1] % range + base
intellect = hash_bytes[2] % range + base
politics = hash_bytes[3] % range + base
charisma = hash_bytes[4] % range + base
```

### 8.3 武將技能

| 技能名 | 類型 | 效果 |
|--------|------|------|
| 衝鋒 | 被動 | 騎兵攻擊力 +20% |
| 鐵壁 | 被動 | 步兵防禦力 +30% |
| 齊射 | 被動 | 弓兵守城加成額外 +25% |
| 火攻 | 主動 | 對目標城造成 AOE 傷害（消耗城防） |
| 水攻 | 主動 | 對行軍中部隊造成減速 + 損耗 |
| 離間 | 主動 | 降低敵方武將加成 50%，持續 1 場戰鬥 |
| 草船借箭 | 被動 | 戰鬥後回復 20% 損失弓兵 |
| 空城計 | 主動 | 有機率讓攻方部隊自動撤退 |

### 8.4 武將升級

- 參與戰鬥獲得經驗值
- 勝利經驗 > 敗北經驗
- 每升一級，隨機 +1~3 屬性點
- 每 10 級解鎖新技能槽

### 8.5 武將交易

- 武將可以在玩家間以 tKAS 交易
- 交易在鏈上結算，確保安全
- 交易手續費：成交價的 5%（進入遊戲獎池）

## 9. 城防系統

### 9.1 城防建築

| 建築 | 效果 | 升級費用 (tKAS) | 最高等級 |
|------|------|-----------------|----------|
| 城牆 | 守方防禦加成 +10%/級 | 10 × 等級 | 10 |
| 箭塔 | 守方弓兵攻擊 +15%/級 | 15 × 等級 | 5 |
| 烽火台 | 偵察視野 +1 城/級 | 20 × 等級 | 3 |
| 兵營 | 訓練速度 +20%/級，容量 +100/級 | 12 × 等級 | 8 |
| 糧倉 | tKAS 儲存上限 +500/級 | 8 × 等級 | 10 |
| 市場 | 交易手續費 -1%/級 | 25 × 等級 | 5 |

### 9.2 升級機制

- 升級消耗 tKAS + 時間
- 城池等級限制建築最高等級（D 城最多蓋到 3 級，S 城最多 10 級）
- 城防被攻破後降級（每次被攻破 -1 級）

### 9.3 修復

- 戰後城防需要修復
- 修復費用 = 升級費用 × 30%
- 修復時間 = 升級時間 × 50%

## 10. 結盟系統

### 10.1 聯盟基礎

- 任何玩家可以花 **50 tKAS** 創建聯盟
- 聯盟最多 **20 人**
- 聯盟有盟主（創建者）和副盟主（最多 3 人）

### 10.2 聯盟功能

| 功能 | 說明 |
|------|------|
| 共享視野 | 盟友的偵察範圍全部共享 |
| 聯合攻擊 | 多個盟友同時對一座城發動進攻，兵力合計 |
| 聯盟聊天 | 盟內即時通訊 |
| 聯盟倉庫 | 盟友可以捐獻 tKAS 到公庫，用於聯盟戰爭 |
| 領土標記 | 聯盟佔領的城池在地圖上顯示統一顏色 |

### 10.3 外交系統

- 聯盟之間可以**結盟**（互不攻擊，共享部分視野）
- 可以**宣戰**（取消結盟保護，開戰通知）
- 可以**背刺**（不宣而戰，但會獲得「背信」標記，24 小時內其他聯盟對你攻擊加成 +20%）

### 10.4 勝利條件（賽季制）

每個賽季（例如 30 天），達成以下之一即為「天下統一」：

- 單一聯盟控制 **洛陽 + 長安 + 成都 + 建業 + 鄴城** 五座核心城持續 **48 小時**
- 賽季結束時佔城總產出最高的聯盟

勝利聯盟成員分享賽季獎池 tKAS。

## 11. 經濟系統

### 11.1 tKAS 流向

```
                  ┌─────────────┐
        產出 ───→ │   玩家錢包   │ ←─── 戰利品
                  └──────┬──────┘
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
     ┌─────────┐  ┌───────────┐  ┌──────────┐
     │ 訓練兵   │  │ 招募武將   │  │ 升級城防  │
     └─────────┘  └───────────┘  └──────────┘
          │              │              │
          ▼              ▼              ▼
     ┌─────────────────────────────────────┐
     │          遊戲經濟池 (銷毀/回收)        │
     └─────────────────────────────────────┘
```

### 11.2 經濟平衡設計

| 項目 | 機制 |
|------|------|
| **通膨控制** | 城池產出隨佔領時間遞減（首週 100%，之後每週 -5%，最低 50%） |
| **tKAS 銷毀** | 訓練兵、招募武將消耗的 tKAS 部分銷毀（50%），部分進入獎池（50%） |
| **戰爭稅** | 攻城勝利時，戰利品的 10% 進入賽季獎池 |
| **交易稅** | 玩家交易手續費 5% 進入獎池 |

### 11.3 玩家間交易（市場）

- 武將交易：掛牌出售 → 其他玩家購買 → 鏈上結算
- tKAS 贈送：直接轉帳給其他玩家
- 未來可能：兵種交易、城池交易

### 11.4 反外掛 / 反刷幣

- 所有經濟操作鏈上記錄
- 同一玩家反覆攻打自己的小號城池，戰利品遞減（24 小時內同路線 -50%/次）
- 新帳號 24 小時保護期內不可被攻擊，但也不可攻擊他人

### 12.4 戰鬥數值範例

**場景：200 騎兵（武將統率 60）攻擊城防 3 級、100 步兵守城**

```
攻方戰鬥力 = 200 × 8 × 1.5(剋制) × (1 + 60/100) = 200 × 8 × 1.5 × 1.6 = 3840
守方戰鬥力 = 100 × 6 × 1.0 × (1 + 3×0.1) = 100 × 6 × 1.3 = 780

攻方勝
攻方損失 = 200 × (780/3840) × 0.6 ≈ 24 騎兵
守方全滅
```

## 14. 技術架構

### 14.1 整體架構

```
┌───────────────────────────────────────────────┐
│                   客戶端 (Web)                  │
│  Godot Web Export / 或 HTML5 Canvas + JS       │
│  手機瀏覽器優先                                  │
└──────────────────┬────────────────────────────┘
                   │ WebSocket + REST API
                   ▼
┌───────────────────────────────────────────────┐
│                 遊戲伺服器                      │
│  Node.js + TypeScript                         │
│  ├── 行軍計時器 (setTimeout / 排程系統)          │
│  ├── 戰鬥結算引擎                               │
│  ├── 城池產出排程                               │
│  └── WebSocket 推送（即時狀態更新）              │
└──────────────────┬────────────────────────────┘
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
┌──────────┐ ┌──────────┐ ┌──────────────┐
│ PostgreSQL│ │  Redis   │ │ Kaspa Node   │
│ 遊戲資料  │ │ 即時狀態  │ │ tKAS 結算    │
│ 玩家/城池 │ │ 行軍佇列  │ │ 武將 mint    │
└──────────┘ └──────────┘ └──────────────┘
```

### 14.2 技術選型

| 層級 | 技術 | 理由 |
|------|------|------|
| 前端 | Godot 4 Web Export 或 Phaser.js | Godot 有成熟 2D 引擎；Phaser 更輕量 |
| 後端 | Node.js + TypeScript | 與 Kaspa SDK 相容，JS 生態豐富 |
| 資料庫 | PostgreSQL | 關聯式資料，城池/玩家/戰報 |
| 快取 | Redis | 行軍佇列、即時狀態、排行榜 |
| 即時通訊 | WebSocket (ws / Socket.IO) | 行軍動畫、戰報推送 |
| 區塊鏈 | Kaspa Testnet (tKAS) | 經濟結算、武將 mint |
| 部署 | Docker + VPS | 初期單機部署 |
| 域名 | kas.openclaw-alpha.com/sanguo/ | Cloudflare Tunnel |

### 14.3 鏈上 vs 鏈下

| 項目 | 鏈上 (Kaspa) | 鏈下 (伺服器) |
|------|-------------|--------------|
| tKAS 餘額 | ✅ | 快取 |
| tKAS 轉帳 | ✅ | — |
| 武將 mint | ✅ (NFT-like) | 屬性快取 |
| 戰鬥結算 | ❌ (太頻繁) | ✅ |
| 行軍狀態 | ❌ | ✅ |
| 城池歸屬 | 定期同步 | ✅ 即時 |
| 交易紀錄 | ✅ | 快取 |

## 17. 風險與對策

| 風險 | 影響 | 對策 |
|------|------|------|
| Kaspa 鏈上交易太慢 | 經濟體驗差 | 鏈下快取 + 批次結算 |
| 玩家太少，地圖空曠 | 無趣 | NPC 城池活躍、AI 對手 |
| 大戶壟斷 | 新手流失 | 保護期、城池產出遞減、賽季重置 |
| 外掛 / 機器人 | 破壞平衡 | 錢包簽名驗證、行為偵測 |
| 手機效能 | 地圖卡頓 | 輕量渲染、按需載入 |
| 法規風險 | 遊戲幣 vs 真錢 | testnet 代幣無真實價值聲明 |
